# System Overview

## The 11-Stage Pipeline

The Rapporteur CLI executes up to 11 stages in a fixed order. Each stage is a self-contained class with a `run()` method that reads from and writes to the build directory. Stages can be selected individually or combined — the pipeline executes only the requested stages, in order.

| # | Stage | Flag | Class | Purpose |
|---|-------|------|-------|---------|
| 1 | Export | `--export` | `ExportStage` | Pull conversations from frontend API or copy static file |
| 2 | Parse | `--parse` | `ParseStage` | Classify turns, build citation map, generate footnotes |
| 3 | Chapters | `--chapters` | `ChapterStage` | Render sessions to Markdown with per-chapter references |
| 4 | Kaliya | `--kaliya` | `KaliyaStage` | Match threat clusters to cached analyses, inject sections |
| 5 | EO Link | `--eo-link` | `EOLinkStage` | Map .gov/.mil comms to EO framework (7-phase sub-pipeline) |
| 6 | Format | `--format` | `FormatStage` | Apply LLM-based style formatting (FLASH rules) |
| 7 | Conclude | `--conclude` | `ConcludeStage` | Generate conclusion chapter (two-call synthesis) |
| 8 | Edit | `--edit` | `EditStage` | Editorial review via LLM (review → apply pattern) |
| 9 | Cite | `--cite` | `CiteStage` | Resolve citation tokens to APA format |
| 10 | Introduce | `--introduce` | `IntroduceStage` | Generate introduction chapter (two-call synthesis) |
| 11 | Publish | `--publish` | `PublishStage` | Build PDF via Sphinx (MyST-parser + LaTeX) |

## Multi-Provider LLM Orchestration

The pipeline uses multiple LLM providers, each selected for its strengths:

| Provider | Model | Stages | Rationale |
|----------|-------|--------|-----------|
| Gemini Flash | `gemini-2.5-flash` | Format | Fast, cheap — mechanical style reformatting |
| Gemini Pro | `gemini-3.1-pro-preview` | EO Link (Phase 3) | Reasoning-high — cross-document EO linkage analysis |
| OpenAI GPT-5.x | `gpt-5.4` / `gpt-5.1` | Conclude, Edit, Introduce | Superior editorial reasoning, configurable reasoning effort |

LLM selection is per-stage via `document.yaml` configuration. Each stage tracks token usage (input, output, thinking) and estimates cost using provider-specific pricing tables.

## Data Flow

The pipeline transforms data through a well-defined directory structure:

```
{build_dir}/
├── raw/                    # Stage 1: Exported conversations
│   ├── conversations_{ts}.json
│   └── conversations.json  # Stable pointer
├── parsed/                 # Stage 2: Classified turns + citation maps
│   ├── session_NNN.json
│   ├── footnotes.json
│   ├── unified_citations.json
│   └── threat_clusters.json  # Stage 3 output
├── chapters/               # Stage 3–10: Chapter markdown files
│   ├── 00-introduction.md  # Generated by Stage 10
│   ├── 01-chapter-slug.md  # Generated by Stage 3, enriched by 4–9
│   ├── ...
│   ├── NN-conclusion.md    # Generated by Stage 7
│   ├── index.md            # Table of contents
│   └── manifest.json       # Build checkpoint & metadata
├── kaliya/                 # Stage 4: Converted figure images
│   └── images/*.jpeg
├── _sphinx_src/            # Stage 11: Sphinx build input
│   ├── conf.py
│   ├── index.md
│   └── *.md (cleaned copies)
├── _build/                 # Stage 11: Sphinx output
│   └── latex/*.pdf
└── {project_slug}.pdf      # Final publication
```

## Command-Line Interface

```
python -m src.components.publisher.rapporteur_cli [-h]
    [--export] [--parse] [--chapters] [--kaliya]
    [--eo-link | --no-eo-link]
    [--format | --no-format]
    [--conclude | --no-conclude]
    [--edit | --no-edit]
    [--cite | --no-cite]
    [--introduce | --no-introduce]
    [--publish] [--all]
    [--force] [--dry-run] [--build-dir DIR]
    [--frontend-url URL] [--edit-chapter FILE]
    [--edit-instructions TEXT]
    [--exclude-eos EO [EO ...]]
    [-v]
    config
```

### Positional Arguments

| Argument | Description |
|----------|-------------|
| `config` | Path to `document.yaml` configuration file |

### Stage Flags

Stages can be combined freely. The pipeline executes only selected stages, always in the canonical order (1–11). Use `--all` to run every stage.

Stages with `--no-` variants (format, conclude, edit, cite, introduce, eo-link) can be disabled even when enabled in `document.yaml`.

### Options

| Flag | Description |
|------|-------------|
| `--force` | Override idempotency guards — re-run stages even if already completed |
| `--dry-run` | Preview actions without writing files |
| `--build-dir DIR` | Override build directory from config |
| `--frontend-url URL` | Override frontend API URL from config |
| `--edit-chapter FILE` | Target a specific chapter for editorial review (filename substring) |
| `--edit-instructions TEXT` | Custom editorial instructions for targeted chapter edit |
| `--exclude-eos EO [EO ...]` | EO numbers to exclude from diagrams and tables (e.g., `14165 14370`) |
| `-v`, `--verbose` | Enable debug logging |
